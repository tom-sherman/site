# @repo/atproto-client

Typed AT Protocol lexicon schemas, generated with [`@atproto/lex`](https://npmx.dev/package/@atproto/lex).

Installed lexicons: `app.bsky.feed.post`, `com.atproto.sync.getLatestCommit`, `com.atproto.sync.getRepo`, `fm.teal.feed.play`

Authored here: `is.sherman.unspecced.thread` (see [Our own lexicons](#our-own-lexicons))

## Usage

Add the package and its peer dependency:

```json
{
  "dependencies": {
    "@atproto/lex": "catalog:",
    "@repo/atproto-client": "workspace:*"
  }
}
```

```ts
import { l } from "@atproto/lex";
import { app } from "@repo/atproto-client";

const record: app.bsky.feed.post.Main = {
  $type: "app.bsky.feed.post",
  text: "hello",
  createdAt: l.currentDatetimeString(),
};

const result = app.bsky.feed.post.$safeParse(record);
```

Each lexicon also exposes `$parse`, `$validate`, `$isTypeOf`, `$build` and friends. Runtime utilities (`xrpc`, `l`, …) come from `@atproto/lex` directly.

### Effect

`@repo/atproto-client/effect` wraps lex's `xrpc` and `$parse` for [Effect](https://effect.website) (`effect` is an optional peer dependency):

```ts
import { com } from "@repo/atproto-client";
import { parse, xrpc } from "@repo/atproto-client/effect";

// Effect<XrpcResponse<…>, XrpcError, HttpClient>
const repo = xrpc("https://pds.example", com.atproto.sync.getRepo, {
  params: { did },
});

// Effect<app.bsky.feed.post.Main, LexParseError>
const post = parse(app.bsky.feed.post, value);
```

Requests go through the `HttpClient` in context, so they're traced, interruptible, and can be swapped out in tests; lex still does the encoding, response validation and error decoding. Failures are `XrpcError`s carrying the lexicon error name, HTTP status and lex's `retryable` verdict, plus `retryAt` (epoch ms) when the service sent `Retry-After` or `RateLimit-Reset`. Lex's own retry loop isn't used, so use `Effect.retry` instead.

The package must be built before it can be imported. Turbo builds it automatically ahead of a dependent's `build` (via `^build`) and `check-types` (via `^check-types`, which depends on `build` here), but not ahead of `dev`, so run `pnpm build` here first on a fresh checkout.

## How it works

```
lexicons.json      manifest of installed lexicons + pinned CIDs  (committed)
lexicons/          lexicon JSON, incl. transitive deps            (committed)
src/index.ts       public entrypoint                              (committed)
src/lexicons/      generated by `lex build`                       (gitignored)
src/**/*.js        emitted by `tsc` alongside the .ts sources     (gitignored)
```

`pnpm build` runs `lex build --clear && tsc`. The JS is emitted next to the TS so the package works both in bundlers and in Node's native TypeScript support, which refuses to strip types under `node_modules`. `types` points at `src/index.ts`, so TypeScript consumers type-check against the source.

## Maintenance

Run these from this package directory.

Add a lexicon:

```sh
pnpm lex:install app.bsky.actor.profile
pnpm build
```

Then export its top-level namespace from `src/index.ts` if it isn't already (e.g. `com`), update the list above, and commit `lexicons.json` and `lexicons/`.

Update all installed lexicons to their latest published versions:

```sh
pnpm lex:install --update
```

Verify `lexicons/` matches the manifest (for CI):

```sh
pnpm lex:install --ci
```

### Our own lexicons

Lexicons under `is.sherman.unspecced` are written by hand in `lexicons/is/sherman/unspecced/`, not installed. `lex install` leaves them alone because they aren't in `lexicons.json`, and `pnpm build` generates them like any other. Export the `is` namespace from `src/index.ts` (already done).

They're unspecced: records only this site reads, so the lexicons aren't published and can change freely.

- `is.sherman.unspecced.thread`: calls out one of my Bluesky threads as writing, so the activity feed shows it as one item. `subject` is a strong ref to the thread's first post, in the same repo, by DID. `title` is optional.

### Notes

- `lexicons.json` lists only the lexicons you asked for, but `lexicons/` also contains everything they reference (embeds, actor defs, etc.). Don't edit either by hand, apart from our own lexicons above.
- Both are in the root `.prettierignore` because `lex install` rewrites them in its own format.
- Don't edit anything under `src/lexicons/`; it's wiped on every build.
